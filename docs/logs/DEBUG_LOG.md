# SDR 核心技術日誌 (Debugging & Development Log)

**記錄從底層硬體控制到數位協議解碼的開發歷程與技術決策。**

---

## Phase 1：環境層與底層驅動除錯

### 挑戰：缺少核心動態連結庫 (DLL)
*   **現象**：載入 `pyrtlsdr` 時直接拋出 `ImportError: Error loading librtlsdr`。
*   **分析**：Python 套件只是個 API 封裝 (Wrapper)，底層還是要靠 C 語言編譯的 `.dll` 驅動檔去跟硬體講話。沒有它，Python 根本叫不動 RTL-SDR。
*   **處置**：與其手動下載、設定系統路徑，不如直接透過 `pip install pyrtlsdrlib`，讓套件自動把正確架構的 DLL 配置到運行環境裡。
*   **結果**：腳本順利初始化，成功打通 Python 與硬體之間的控制橋樑。

---

## Phase 3：數位訊號處理 (DSP) 實戰

### 挑戰：SDR 接收器資源咬死 (Access Denied)
*   **現象**：腳本異常中斷後，重啟會跳出 `LIBUSB_ERROR_ACCESS (-3)`，不給跑。
*   **分析**：在 Windows 系統下，如果程式沒有正常退出（未觸發 `sdr.close()`），USB 的控制權 (Handle) 不會被釋放。系統覺得「還有人在用」，導致硬體狀態機整個掛死。
*   **處置 SOP**：
    1.  強制 Kill 所有背景的 Python 執行緒。
    2.  如果依然鎖死，代表是 Driver 層級的問題。直接物理拔插 USB，或是去電腦的裝置管理員重啟該節點。
*   **技術備註**：跟硬體打交道就是這樣，資源的佔用是獨佔性的。這突顯了未來在主程式實作嚴謹例外處理 (Try/Finally 資源釋放) 的絕對必要性。

## Phase 3.1：狙擊 19kHz (Pilot Tone)

### 實作：極窄帶帶通濾波器
*   **目標**：從廣播基頻中，把用來做立體聲同步的 19kHz 導頻 (Pilot Tone) 獨立抽出來。
*   **參數配置**：
    *   **取樣率 (FS_RF)**：2.4 MSPS，確保訊號細節夠多。
    *   **降取樣 (Decimation)**：訊號進來後先砍 10 倍變 240 kHz，減輕運算壓力。
    *   **濾波器 (Filter)**：實作一個 255-tap 的 FIR 帶通濾波器，頻寬砍得很窄（只留 18.5k - 19.5k）。
*   **成果**：時域波形畫出來是非常純淨的正弦波。抓到這個波，等於拿到了解開 FM 立體聲密碼的「時鐘基準」。

## Phase 3.2：解析 FM 頻譜的隱藏架構

### 實作：多副載波同步分離
*   **目標**：不只抓 19kHz，還要同時把 38kHz (立體聲 L-R) 跟 57kHz (RDS 數位廣播) 一次解出來看。
*   **觀察結果**：
    *   **38kHz (立體聲差分訊號)**：這是一道振幅調變 (DSB-SC) 的載波，波形會跟著正在播放的音樂劇烈跳動。
    *   **57kHz (RDS 數位訊號)**：波形跟前面完全不同，呈現一塊一塊的數位特徵，這是 BPSK 調變的證據。
*   **技術總結**：這是一次教科書級別的「頻分多路複用 (FDM)」解剖。證明我們可以從一條天線收到的複雜波形裡，把不同的資訊流精準切開。

## Phase 3.3：立體聲矩陣還原 (Stereo Matrix)

### 實作：混頻器與左右雙聲道分離
*   **技術突破**：成功把數學公式變成聽得到的左右聲道。
*   **解碼邏輯**：
    1.  把前面抓到的 19kHz 導頻拿去「平方」，直接生出完美同步的 38kHz 載波，連複雜的鎖相迴路 (PLL) 都省了。
    2.  把這道載波跟主訊號做混頻 (Mixing)，然後過低通濾波器，就能還原出被隱藏的 (L-R) 差分聲道。
    3.  最後套矩陣公式：把 0-15kHz 的 (L+R) 拿去加減 (L-R)，算出真正的左耳跟右耳聲音。
*   **音質提升 (De-emphasis)**：因為發射站會把高頻放大來抗噪，接收端沒弄好就會很刺耳。實作了一個 50μs 時間常數的一階 IIR 數位濾波器（也就是「去加重」），加上去之後高頻雜音殺光，音色立刻變得厚實溫潤。

### 技術探討：為什麼立體聲不直接傳 Left 跟 Right？
如果是直接傳左邊和右邊，以前買單聲道收音機（只能吃 0-15kHz）的人，聽歌就會少一半的樂器聲。  
所以廣播的設計是：
*   **主頻段 (0-15kHz)** 傳 **(L+R)**。單聲道收音機聽這個，有完整的聲音。
*   **副載波 (38kHz)** 偷傳 **(L-R)**。立體聲收音機有能力解開它，再去跟前面做加減，算出空間感。  
這是在不佔用額外頻寬的前提下，做到完美「向後相容」的工程傑作。

## Phase 3.4：數位化最後一哩路 (RDS Bitstream Extraction)

### 實作：從類比波形榨出數位 0 與 1
*   **目標**：把 FM 頻帶最邊緣的 57kHz 訊號，反編譯成電腦看得懂的位元串流 (Bitstream)。這也是從「聽廣播」跨越到「數位通訊情報擷取 (SIGINT)」的關鍵戰役。
*   **DSP 執行鏈**：
    1.  **Costas Loop (載波鎖定)**：RDS 是 BPSK 調變（靠相位不同來區分 0 和 1）。寫了一個二進制鎖相迴路來對齊 57kHz 的相位，把波形拍平。
    2.  **時鐘還原 (Bit Sync)**：RDS 的傳輸速度是 1187.5 Hz。寫了一個掃描器找出波峰最穩定的那瞬間去採樣（Sampling），把連綿不絕的電壓轉換成離散的陣列。
    3.  **差分解碼 (Differential Decoding)**：因為相位有可能翻轉，RDS 不傳絕對的 0 或 1，而是傳「有沒有變」。用一個簡單的 XOR 運算 （$b_n = d_n \oplus d_{n-1}$）把原始位元推算出來。

## Phase 3.6：狀態機與文字轉譯 (The RDS Decoder)

### 實作：CRC 訊框鎖定與文字拼湊
拿到無止盡的 0 跟 1，要怎麼知道哪裡是一句話的開頭？這就是通訊協議最硬核的地方。
*   **分段採樣架構**：為了解決 USB 緩衝區爆炸（Short read 報錯），把架構從「一次讀完」改成「每 0.5 秒讀一次並拼接」，確保長時間採樣不中斷。
*   **Syndrome 同步 (Frame Sync)**：
    *   RDS 是以 26-bit 為一個區塊。
    *   寫了一個多項式除法器一直去滑動計算「餘數 (Syndrome)」。只要餘數等於特定的 A, B, C, D 偏移字 (Offset Word)，狀態機立刻宣告「鎖定邊界」！
*   **現況驗證**：在辦公室室內，雖然因為干擾導致整體誤碼率極高，但狀態機成功捕捉到了同步特徵並報出 `PI (電台身份碼)`。這在開發層面上證明了：**整套從物理學到應用層的數學模型完全正確。**
