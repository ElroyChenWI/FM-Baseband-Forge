# 解構 FM 實體層：從電磁波到 RDS 數位字串的 DSP 全鏈路實作

> "In the world of RF, you don't just read bits. You fight physics to earn them."

本專案實作了一個基於 Software Defined Radio (SDR) 的 FM 廣播接收器。本實作並未依賴現成的 GNU Radio 黑盒子模組或高度封裝的通訊函式庫，而是堅持使用 Python 原生科學計算生態系 (Numpy/Scipy)，從高解析度複合基頻 (Composite Baseband) 訊號開始，從無到有手刻軟體鎖相迴路 (Software PLL)、立體聲解碼矩陣 (Stereo Matrix)、以及複雜的 RDS (Radio Data System) BPSK 數位解碼管線。此開發歷程徹底展示了對通訊底層理論的深厚掌握度。

---

## 核心破局點：載波 (Carrier) 與 調變 (Modulation) 的物理隔離

在 RDS 解碼的實務開發中，最容易讓純軟體工程師卡關的技術盲點，在於將「57kHz 頻率」與「BPSK 訊號」混為一談。在底層通訊物理學中，這兩者絕對是「承載工具」與「負載訊號」的分立關係：

57kHz 副載波 (The Carrier)
這是一條中心頻率為 57,000 Hz 的純粹正弦波 C(t) = cos(2π * 57000 * t)。它本身並不攜帶任何數位情報資訊，其唯一作用是為了將數位訊號的頻譜搬移至人類聽覺感知不到的高頻專用帶上，從而避免干涉或污染 0~15kHz 的 FM 主音訊頻道。

BPSK 調變 (The Modulation)
二位元相位偏移調變 (Binary Phase Shift Keying)。廣播發射設備並不會改變載波波形的振幅大小，而是透過「瞬間翻轉 180 度載波相位」來代表底層數位資料邏輯的 0 與 1。

物理真相
為了極大化頻段的頻譜效率與節省發射功率，現代 FM 發射端會故意將單純的 57kHz 載波能量抽掉，也就是所謂的抑制載波 (Suppressed Carrier) 技術。因此接收端天線實際抓取到的頻域資料，並不是一道高能量的單純正弦波，而是一個會隨著數位資料頻繁在正反相位間跳動的 DSB-SC (雙邊帶抑制載波) 複合波包。

## RDS 數位解碼「黃金四階段」管線 (Pipeline)

要將飄散在高空中、極易受多徑干擾 (Multipath Fading) 的微弱 BPSK 波包，精確還原成人類可讀文字，演算法必須嚴格且序列地執行以下 4 個 DSP (數位訊號處理) 處理階段。這些階段的順序具有絕對的相依性，任何一步的時序誤差都會導致後續管線發生雪崩式的錯誤。

### Phase 1: 載波同步與降頻 (Carrier Synchronization & Down-conversion)

挑戰： 空氣中的電磁載波並未夾帶 57kHz 的絕對時鐘基準，接收端無法直接得知發射端的初始相位。

解法： 利用 FM 複合頻譜中具有極高環境穩定性的 19kHz 導引音 (Pilot Tone) 作為初始相位參考點，建立高度追蹤能力的 Software PLL (軟體鎖相迴路)。將鎖定後的精確相位乘以 3 倍，在軟體記憶體中無中生有地生成一把完美的 57kHz 本地載波鑰匙。

DSP 動作： 將原始擷取到的 RF 訊號陣列與這把本地鑰匙進行矩陣相乘（軟體混頻操作）。透過三角函數的和差化積抵銷作用，將 57kHz 的載波頻率徹底拔除，將高空中不斷翻轉相位的 BPSK 訊號，硬生生「擊落」回 0 Hz (Baseband) 的基頻狀態。

### Phase 2: 位元同步與取樣 (Bit/Symbol Synchronization)

挑戰： 降落到 0 Hz 基頻的訊號，在時域上仍是一條連綿起伏的連續類比波浪線，並非我們所需的離散資料陣列。而標準 RDS 規範的傳輸率 (Baud Rate) 嚴格限定為 1187.5 bps。

解法： 實作時序復原演算法，例如 Early-Late Gate 迴路，或是多相位匹配濾波器掃描。

DSP 動作： 演算法必須動態追蹤這條波浪線，在每一個波峰或波谷的絕對正中央（能量最大點）進行最佳取樣 (Sample)，以確保獲得最大的訊雜比 (SNR) 裕度。

產出： 經過取樣器後，系統將產出一長串包含硬體反轉風險的原始位元陣列：raw_bits = [0, 1, 1, 1, 0, 1...]。

### Phase 3: 差分解碼 (Differential Decoding)

挑戰： 由於 Costas Loop 在解調無載波 BPSK 時存在不可避免的相位模糊 (Phase Ambiguity) 物理缺陷。SDR 接收硬體極有可能在接通鎖定的瞬間，把所有的 0 誤判成 1，將 1 誤判成 0。

解法： RDS 發射協議巧妙地採用了「差分編碼」防錯策略——系統傳送的訊號代表的是「相位變化量」而非「絕對電壓邏輯值」。若當前符號與上一 bit 相同則代表資料邏輯的 0，發生相位翻轉則代表邏輯 1。

DSP 動作： 演算法會捨棄第 1 個 bit 作為基準參考點，並針對後續整個位元陣列執行位移 XOR (互斥或) 運算。

```python
import numpy as np
# 藉由差分運算，巧妙繞過硬體相位反轉的物理缺陷，還原真實邏輯
decoded_bits = np.bitwise_xor(raw_bits[1:], raw_bits[:-1])
```

產出： 犧牲單一位元後，即可洗出絕對正確、免疫全域翻轉的真實位元流 (True Bits)。

### Phase 4: 幀同步與解析 (Frame Synchronization)

挑戰： 系統此刻面對的是一條無始無終的 True Bits 陣列，接收端完全沒有任何前導碼 (Preamble) 或同步字元可以辨識資料封包的確切開頭。

解法： 建立一個以 26-bit 為單位的循環滑動視窗 (Sliding Window)。根據 RDS 協議規範，每個 Block (26 bits) 嚴格包含 16 bits 的資訊負荷資料，外加 10 bits 的循環冗餘校驗碼 (CRC，且此校驗碼已與特定的 Offset Word 進行過 XOR 運算)。

DSP 動作： 軟體引擎每滑動一個位元步階，就以矩陣形式進行一次複雜的 10-bit CRC 多項式除法計算。當計算出來的餘數 (Syndrome) 為 0，或是精確匹配 A、B、C、D 等特定偏移字特徵出現的瞬間，狀態機立刻拉高旗標宣告「幀同步成功鎖定」！

產出： 此瞬間滑動視窗內的前 16 bits 即為精確對齊的 Block A 資料區塊。將此區塊的二進位轉為 Hex (十六進位制)，即可順利解碼出該廣播電台全球唯一的身分證字號 PI 碼 (Program Identification)，例如 D010。

## 實戰 Debug 案例：射頻前端飽和與混疊干擾 (Front-end Overload)

現象描述
在實際場域的系統整合測試階段，軟體 NCO (數值控制振盪器) 的頻率明確鎖定於 94.3 MHz (預估該頻段目標應為警察廣播電台)，然而 RDS 解碼管線最終卻極其穩定地解碼出 PI: D010 (經交叉比對資料庫查證為亞洲電台，但其真實實體發射頻率應落在 92.7 MHz 頻段)。

架構師物理診斷
經過全面的邏輯追蹤，確認這並非 DSP 演算法程式碼的 Bug 出錯，而是硬體物理極限在極端惡劣電磁環境下的真實展現。

ADC 飽和 (ADC Clipping)
由於測試開發環境的物理位置距離亞洲電台的高功率射頻發射塔過近（位於桃園中壢區域），空間中異常強大的 RF 射頻訊號直接灌爆了 RTL-SDR 接收器前端廉價的 8-bit ADC (類比數位轉換器)，導致時域上的電壓波形頂端被直接削平。

互調失真 (Intermodulation Distortion)
嚴重飽和且操作於非線性區間的硬體放大器，隨之產生了龐雜的非線性頻譜產物。這導致擁有龐大能量的 92.7 MHz 電台主訊號在頻譜圖上產生了強烈且具有傷害性的鏡像分身 (Aliases)，而這個無效的鏡像頻段剛好直接覆蓋、完全癱瘓了原本座落於 94.3 MHz 頻段上相對微弱的目標警廣訊號。

結論驗證
這個特殊的失敗案例反而有力地證明了本軟體系統的極限解碼能力。儘管底層實體硬體受到了嚴重干擾與飽和失真，本專案所實作的 Software PLL 與 Costas Loop 等核心演算法依然表現出極高的強健性 (Robustness)。它成功從嚴重混疊的骯髒波形中識別並鎖定殘存的最強基頻載波，並分毫不差地精準完成了所有的差分解碼以及 CRC 錯誤驗證機制。

解決方案
從 RF 工程實務觀點出發，未來優化可於 SDR 的驅動控制層大幅調降 RF Gain (射頻硬體增益) 設定，以擴展大訊號動態範圍避免 ADC 截斷；或是最直接有效地，於硬體天線前端實體串接針對該強烈在地訊號源的 FM Trap 帶阻濾波器 (Band-stop Filter/Notch Filter)，即可徹底排除此物理層面的訊號污染。
